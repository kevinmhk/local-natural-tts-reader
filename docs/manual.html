01

Before you begin

Confirm the machine and understand when the reader uses the network. The supported current runtime is deliberately narrow.

Hardware and software requirements

  • An Apple-silicon Mac. In Terminal, uname -m should print arm64.
  • macOS with the built-in /usr/bin/afplay utility.
  • git to obtain or update the source checkout.
  • uv to install Python 3.12 and the project environment.
  • At least 3 GB free for the default model, plus room for generated WAV files.
!

Two network phases onlyCloning the repository, installing dependencies, and running reader models setup need internet access. Importing, previewing, synthesizing, caching, and playback are local after setup.

Supported documents

FormatExtensionsWhat is readMain limitation
Plain text.txtBlank-line paragraphs with encoding detectionPresentation structure is limited
Markdown.md, .markdownHeadings, prose, list text, labels, inline codeCode blocks and raw HTML are omitted
Local HTML.html, .htmMain article prose without remote fetchingTables, navigation, scripts, and images are omitted
Born-digital PDF.pdfPage text with conservative header and page-number cleanupScans need OCR; complex reading order must be previewed

EPUB, DOCX, image OCR, remote URLs, voice cloning, and voice design are not part of the MVP.

02

Install

Keep everything project-local. The commands below create a locked Python 3.12 environment inside the repository and install the MLX-Audio option.

  1. Install uv if needed

    With Homebrew:

    Terminal
    brew install uv

    Or use Astral's standalone installer:

    Terminal
    curl -LsSf https://astral.sh/uv/install.sh | sh

    See the official uv installation guide before running a downloaded installer if you want to inspect it or choose another method.

  2. Obtain the project

    Terminal
    git clone https://github.com/kevinmhk/local-natural-tts-reader.git
cd local-natural-tts-reader

    If you already have the checkout, open Terminal in its root directory instead.

  3. Create the environment and install dependencies

    Terminal
    uv python install 3.12
UV_CACHE_DIR=.cache/uv uv sync --group dev --extra mlx

    The first line is safe to repeat; uv also installs a missing compatible Python automatically. The sync command creates .venv, installs the locked dependencies from uv.lock, and registers the reader command in that environment.

  4. Run the platform inspection

    Terminal
    UV_CACHE_DIR=.cache/uv uv run --extra mlx reader doctor

    Look for python_312: true, apple_silicon: true, macos: true, an afplay path, and sufficient disk space. model_available is expected to be false before the next section.

03

Model setup

Model acquisition is explicit. Normal reading never downloads a missing model in the background.

!

Review the configuration firstThe first reader command creates ~/.local-natural-tts-reader/config.toml. Edit its data_dir before model setup if you want a different workspace. See Configuration for the complete file.

Download the tested default model

Network required / once
UV_CACHE_DIR=.cache/uv uv run --extra mlx reader models setup

This installs mlx-community/Qwen3-TTS-12Hz-1.7B-CustomVoice-6bit in the reader's configured data directory. It is approximately 3 GB and can take several minutes.

Verify it with network access disabled

Offline verification
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  UV_CACHE_DIR=.cache/uv uv run --no-sync reader models verify

A successful response contains "available": true and the resolved local path.

Pin a particular upstream revision

Advanced users can explicitly download a revision. The installed Hugging Face commit is automatically included in future cache identities.

Optional
uv run --no-sync reader models setup \
  --model mlx-community/Qwen3-TTS-12Hz-1.7B-CustomVoice-6bit \
  --revision REVISION
OK

What setup does not downloadDocuments are not part of model setup. No source text is sent to Hugging Face or another service.

04

Configuration

The first reader command creates one human-editable TOML file. It stores the workspace, narration defaults, and operational limits locally; no application environment variable is needed.

Default configuration and data directory

The default configuration file and local workspace are:

Default path
~/.local-natural-tts-reader/config.toml
~/.local-natural-tts-reader/

Run reader doctor once to create the file, then edit it with your preferred text editor. Its complete default content is:

TOML configuration
# Local Natural TTS Reader configuration.
# Edit this file, then run `reader doctor` to verify the result.

# All sources, previews, SQLite state, generated WAVs, and reader-managed models.
data_dir = "~/.local-natural-tts-reader"

# Default Qwen3-TTS CustomVoice narration profile.
default_model = "mlx-community/Qwen3-TTS-12Hz-1.7B-CustomVoice-6bit"
default_voice = "Aiden"
default_language = "English"
default_instruction = "Calm, clear long-form narration with restrained expression and natural pauses."
default_speed = 1.0

# Safety, chunking, and pacing limits. Keep Qwen3-TTS chunks short.
max_file_bytes = 104857600
max_pdf_pages = 2000
chunk_target_chars = 280
chunk_hard_limit_chars = 360
paragraph_pause_ms = 350
section_pause_ms = 800
min_free_bytes = 268435456
!

Use one configuration consistentlyModels, document IDs, cache records, and resume positions live in its configured data_dir. Commands that use a different configuration file appear to have a different library.

The former default pair of 1200 and 1800 is automatically migrated once to 280 and 360 when the reader next loads the configuration. This changes only future imports; existing documents retain their saved chunk manifests until explicitly rebuilt.

For a separate profile or an isolated test workspace, put --config before the reader subcommand. A missing config is created and initially uses its parent directory as the workspace:

05

First listening session

This is the recommended human workflow: import, read the preview, then synthesize. Preview is not optional for layout-heavy PDFs.

  1. Import a local document

    Use quotes for spaces
    uv run --no-sync reader ingest "/absolute/path/to/My Document.pdf"

    The command copies the source into immutable local storage, extracts text, cleans it, creates deterministic chunks, and prints JSON. Copy the value of document_id. If you forget it later, use reader documents list.

  2. Inspect exactly what will be spoken

    Replace the ID
    uv run --no-sync reader preview DOCUMENT_ID --stdout

    The metadata includes a preview_path. The text printed after it is the exact cleaned narration input. Check warning messages and reading order before continuing.

  3. Start narration

    Default Aiden profile
    uv run --no-sync reader speak DOCUMENT_ID

    The first chunk is synthesized, validated, and played through afplay. The next chunk generates in the background. Audio is cached as complete WAV files.

  4. Confirm completion

    Status
    uv run --no-sync reader status DOCUMENT_ID

    A finished session reports "state": "complete". Running the same speak command again should report cache hits instead of regenerating matching audio.

06

Daily use

The ordinary loop is small: reuse the same configuration, import a file, preview, speak, and use the local document list whenever you need to recover an ID.

Find an earlier document

Local library
uv run --no-sync reader documents list

The JSON result lists each document ID with its source name, title, media type, import date, current playback state, chunk progress, warning count, and total cached-audio duration.

Delete an imported document

Inspect first
uv run --no-sync reader documents delete DOCUMENT_ID --dry-run

The dry run reports the document directory, SQLite records, cached chunk WAVs, and matching complete exports that would be removed. It changes nothing.

Interactive and permanent
uv run --no-sync reader documents delete DOCUMENT_ID

The command requires an interactive terminal and asks Continue? [y/N]. It creates no backup, never removes the original source outside the reader workspace, and removes matching exports unless you add --keep-exports. After deletion, it asks Prune every unreferenced WAV in the global cache now? [Y/n].

Choose a narration style

Custom profile
uv run --no-sync reader speak DOCUMENT_ID \
  --voice Aiden \
  --language English \
  --instruction "Warm, measured audiobook narration with clear dialogue and restrained emotion." \
  --speed 1.0

Use only voices supported by the installed CustomVoice model. Aiden is the tested default. Style instructions should describe delivery, not ask the model to summarize or alter content.

Pause from another Terminal window

Cooperative pause
uv run --no-sync reader pause DOCUMENT_ID

The current chunk is stopped and remains unconfirmed, so resume may repeat that chunk but will not skip it.

Resume later

Saved profile and position
uv run --no-sync reader resume DOCUMENT_ID

Resume uses the latest saved narration profile and starts at the last unconfirmed chunk.

Generate without audible playback

Silent generation
uv run --no-sync reader speak DOCUMENT_ID --no-play

Export one complete WAV

Complete cached narration
uv run --no-sync reader export wav DOCUMENT_ID

After all chunks for the latest narration profile are cached, this streams them in order into one PCM WAV under exports/. The name includes the original source filename, document ID, and profile hash so it remains understandable outside the reader. It fails rather than creating a partial document export.

Run a fast diagnostic without MLX

Fake engine
uv run --no-sync reader speak DOCUMENT_ID \
  --engine fake --model fake-tone --no-play

The fake engine creates a short deterministic tone. It tests ingestion, state, cache, and playback coordination without loading Qwen.

08

Document handling

The reader keeps the original, the extracted structure, the cleaned preview, the chunk manifest, and generated audio separate so every stage can be inspected.

What import changes

  • The original source is copied byte-for-byte into the application workspace.
  • A SHA-256 identity makes repeated import of unchanged content idempotent.
  • Extracted and cleaned JSON artifacts are written atomically.
  • The exact narration text is saved as cleaned/preview.txt.
  • Chunks preserve deterministic order and stable identities.
  • No audio is generated until reader speak.

PDF review rules

PDF

Always preview important PDFsPDF stores visual placement rather than dependable semantic structure. Multi-column pages, tables, equations, captions, and footnotes can appear in the wrong order even when text extraction succeeds.

Repeated page-edge lines and isolated page numbers are removed conservatively. An image-only or near-empty PDF exits with a needs_ocr error. Encrypted, malformed, oversized, excessive-page, and signature-conflicting inputs are rejected.

Data layout

Conceptual workspace
~/.local-natural-tts-reader/
|-- config.toml
|-- reader.sqlite3
|-- models/
|-- documents/
|   `-- DOCUMENT_ID/
|       |-- source/
|       |-- extracted/document.json
|       |-- cleaned/document.json
|       |-- cleaned/preview.txt
|       `-- chunks/manifest.json
|-- audio/
|-- exports/SOURCE_NAME-DOCUMENT_ID-PROFILE_HASH.wav
`-- tmp/
09

Offline and privacy

The runtime boundary is the data directory named in the local TOML configuration. There are no accounts, telemetry, analytics, cloud synchronization, or remote document URLs.

Run the supplied offline verification

Fake engine / no audible output
scripts/verify_offline_runtime.sh

To include real local Qwen synthesis, first obtain the exact model path from reader models verify, then run:

Real MLX offline verification
LOCAL_TTS_READER_MODEL_PATH="/absolute/path/to/model" \
  scripts/verify_offline_runtime.sh

Privacy behavior

  • Local HTML is parsed from bytes and does not fetch scripts, styles, images, frames, or links.
  • Full source text is shown only when you explicitly use preview --stdout.
  • The current application writes no persistent log by default.
  • Voice cloning and voice design are unavailable in the MVP.
  • Users remain responsible for rights in source documents, model weights, preset voices, and generated audio.
10

Maintenance

Cache management is explicit and dry-run-first. Updating the checkout does not require deleting your local library or model.

Inspect and prune audio

Safe inspection
uv run --no-sync reader cache inspect
uv run --no-sync reader cache prune --dry-run

Only after reviewing the dry-run count and byte total, delete unreferenced WAV files with:

Destructive / unreferenced WAV only
uv run --no-sync reader cache prune --delete

Cache pruning does not delete files under exports/; remove completed exports manually when you no longer need them.

Update the source checkout

Update and resync
git pull --ff-only
UV_CACHE_DIR=.cache/uv uv sync --group dev --extra mlx

Locate or remove local application data

Open default data directory in Finder
open "$HOME/.local-natural-tts-reader"

Deleting the configured data directory removes imported source copies, cleaned text, generated audio, installed reader-managed models, SQLite state, and resume positions. Back up original documents separately and inspect the exact directory before removing it.

11

Troubleshooting

Start with reader doctor, preserve the exact error message, and verify that every terminal uses the same configuration file.

Model is not installed locally

Run reader models setup once with network access, using the same config.toml that you will use for reading. Then run reader models verify.

MLX-Audio is not installed

From the repository root, rerun UV_CACHE_DIR=.cache/uv uv sync --group dev --extra mlx. Normal commands should then use uv run --no-sync.

Doctor reports the wrong Python or architecture

The supported environment is Python 3.12 on macOS arm64. Run uv python install 3.12 and resync. An Intel Mac or a translated x86 shell is outside the supported MVP profile.

PDF has no useful text layer

The file is probably scanned or image-only. OCR is outside v0.1; use a trusted local OCR tool to create a searchable PDF or extract text first, then import the result.

PDF text is in the wrong order

PDF extraction follows the text layer, not visual semantics. Inspect preview --stdout. For multi-column layouts, tables, equations, or complex footnotes, convert the document to clean text or Markdown before narration.

Playback is silent or fails

Confirm reader doctor shows /usr/bin/afplay, check the Mac output device and volume, and run the same command with --no-play. The reader rejects newly generated WAVs that reach Qwen's generation limit or end with more than three seconds of silence; if that error appears, reduce the configured chunk limits and import a new document after correcting the configuration.

Generation appears slow

The first chunk includes lazy model loading. Later matching runs use complete cached WAV files. Confirm Apple silicon, close memory-heavy applications, and avoid changing voice or instruction settings when you want cache reuse.

A Transformers compatibility warning appears

MLX-Audio 0.4.8 can emit a non-fatal model-type warning while successfully loading this Qwen conversion. If synthesis produces a valid WAV and exits successfully, the warning alone is not a failure. Preserve it when reporting a real generation error.

Low disk space stops synthesis

The reader refuses to start another chunk below its free-space threshold. Run reader cache inspect, review reader cache prune --dry-run, and delete only after confirming the candidates.

A document ID is unknown in another terminal

First run reader documents list in the current terminal. If the ID is still absent, the terminals are probably using different configurations. Run reader doctor in both terminals to compare config_path and data_dir; use the same --config PATH when needed.

12

Quick reference

A compact operating sequence for a machine that has already completed dependency and model setup.

Complete daily workflow
# The first command creates ~/.local-natural-tts-reader/config.toml.
# Edit data_dir there before model setup if you want another workspace.

# Inspect the environment, configuration, and local model.
uv run --no-sync reader doctor
uv run --no-sync reader models verify

# Import and copy the returned document_id.
uv run --no-sync reader ingest "/absolute/path/to/document.pdf"

# Replace DOCUMENT_ID below.
uv run --no-sync reader preview DOCUMENT_ID --stdout
uv run --no-sync reader speak DOCUMENT_ID
uv run --no-sync reader export wav DOCUMENT_ID

# From another terminal if needed.
uv run --no-sync reader pause DOCUMENT_ID
uv run --no-sync reader resume DOCUMENT_ID
uv run --no-sync reader status DOCUMENT_ID
✓

Definition of a healthy runThe preview matches the intended reading order, speak reports complete, a repeated run reports cache hits, and all commands resolve the same data directory.
